## Orchestrator Features

### 1. Checkpoint-Based Resume
- Reads `job_scraper/checkpoints.json` (schema_version 1.0)
- Determines resume point from `current_checkpoint` and `run_history`
- Supports three resume modes:
  - `--resume` — Auto-detect from checkpoint
  - `--start-from <stage>` — Manual stage selection
  - Fresh run — Starts from discovery when all stages complete

### 2. Stage Validation
- `OUTPUTS` map defines expected output files per stage
- Validates files exist before marking stage complete
- Uses aggregated (non-date-stamped) files as authoritative:
  - `canonical_jobs.json`, `seen_jobs.json`
  - `filtered_jobs.json`, `priority_queue.json`
  - `seen_jobs.json` (ranking writes ranks back to seen_jobs)

### 3. CLI Interface
```bash
node job_scraper/orchestrator.js [options]

Options:
  --mode, -m <mode>         Pipeline mode: INCREMENTAL (default) or FULL_AUDIT
  --resume, -r              Resume from last checkpoint
  --start-from, -s <stage>  Start from specific stage
  --dry-run, -d             Show execution plan without running
  --help, -h                Show this help
```

### 4. Progress Logging
- Stage start/complete/skip/failed with icons (▶️ ✅ ⏭️ ❌ 🔄)
- Batch progress within verification/scoring stages
- Final summary with Top 5 jobs

### 5. Error Handling
- Stage failures preserved in checkpoint with error details
- Clear resume instructions on failure
- Non-zero exit code for CI/CD integration

### 6. Testability
- Exports `determineResumePoint`, `getCompletedStages`, `validateStageOutput`, `OUTPUTS`, `STAGES`
- Accepts custom `stageRunners` for mock injection
- 8 unit tests covering resume logic, stage validation, and output mapping
