## 5. Complete Recruiter Journey (anonymous)

Narrative journey (as far as the anonymous surface allows):

1. Landing at `/demo` → `/demo/dashboard` (✔ rendered, KPI cards + Top 5 + pipeline donut + app activity).
2. "Browse All Jobs" → `/demo/jobs` (✔ 50 demo jobs, filters/search/pagination, all client-side over public data).
3. Click any job → `/demo/jobs/:stable_id` → **✘ NetworkError** (private `GET /api/jobs/:id` → 401). The job detail with evaluation radar, fit breakdown, "Track Application", and Save button never renders.
4. "View fit analysis" from detail → `/demo/jobs/:stable_id/fit` → **✘ error** (private `GET /api/jobs/:id` → 401).
5. "View ranking" → `/demo/ranked` (✔ Top5/Top10/All tabs).
6. "All applications" → `/demo/applications` (✔ 16 demo apps rendered, but with the schema-mismatch display defects in Finding F-2).
7. "View pipeline health" → `/demo/pipeline` → **✘ ErrorState** (private `GET /api/pipeline/status` → 401).
8. "Explore ranking & retention" → `/demo/retention` → **✘ ErrorState** (private `GET /api/pipeline/retention` → 401).

**Conclusion:** 4 of the 9 public routes are broken for the anonymous recruiter. The journey is not complete as shipped.

## 20. Findings — Classified

### BLOCKER
**None identified.** No anonymous visitor can read private data, mutate data, or reach a private endpoint. The HTTP-level public/private boundary is closed and verified.

### HIGH
- **F-1 — Four `/demo/*` routes mount private components that call private endpoints.**
  `App.tsx` lines 59–64: `/demo/jobs/:stable_id` → `JobDetail` (`GET /api/jobs/:id`, `GET /api/applications`, `GET /api/saved-jobs`, POST `/api/applications`), `/demo/jobs/:stable_id/fit` → `FitAnalysis` (`GET /api/jobs/:id`), `/demo/pipeline` → `Pipeline` (`GET /api/pipeline/status`), `/demo/retention` → `RetentionStats` (`GET /api/pipeline/retention`). Consequences: (a) 4 of 9 public routes are **broken for anonymous recruiters** (401 → error states) — the "complete unauthenticated recruiter experience" is not delivered; (b) for any **authenticated session** browsing `/demo/*`, those private calls **succeed** and render real private data under public URLs (boundary contamination) — verified live with a valid token (dashboard/applications 200, jobs/demo-001 404 as demo ids are absent from the real store). The P4.1 plan called for public-variant components (`PublicJobDetail` with `usePublicJob`, `PublicRetentionStats` with the public retention shape); none exist at HEAD. Not a confidentiality breach for anonymous users, but a release-readiness defect for 4 intended routes and an architectural boundary violation.

### MEDIUM
- **F-2 — Applications schema mismatch breaks display on `/demo/applications` and the dashboard's Application Activity.**
  Backend `ApplicationRecord` (schemas.py:110–125) and `/api/public/applications` return `date` + `stable_id` only. Frontend `ApplicationRecord` type (types.ts:225–248) and both consumers expect `job_stable_id`, `created_at`, `updated_at`, `id`, `available`, `job`. Effects: job-title column always `—`, "Updated" column always `—`, React row keys `undefined` (duplicate-key warnings), date-sort is a no-op. Data is present and readable (role/company/status/fit_rating correct), but the page is visibly broken in two columns and under cross-referencing.
- **F-3 — Public retention shape has no compatible consumer.**
  `/api/public/retention` returns a flat demo shape (`retention_policy_days`, `state_breakdown` as a **list**, no `retention_policy`/`summary` objects). The only component wired to a retention page (`RetentionStats`) expects the private `RetentionResponse` dict shape. No page consumes the public retention endpoint at HEAD. (Compound with F-1 for `/demo/retention`.)
- **F-6 — Reused private components do not detect public context, so the "read-only demo" claim is not enforced in the UI for authenticated sessions.**
  "Track Application" (`useCreateApplication`) and the Save toggle render unconditionally on `/demo/jobs/:stable_id`. Anonymous visitors are blocked by 401 (no leak), but an authenticated session on the public demo can create real applications/saved-jobs. A public/read-only variant would hide these.

### LOW
- **F-4 — Missing frontend tests for P4.1 public surface.** No `Public*.test.tsx` / `PublicRoute.test.tsx` files exist at HEAD; the 4 broken routes and the schema mismatches are uncovered.
- **F-5 — Pre-existing deprecation warnings** (`datetime.utcnow()`, pytest-asyncio event-loop policy) in test runs; informational, out of scope.
- **F-7 — Loading/skeleton vs error:** `PublicDashboard` aggregates 4 queries for its loading gate (fine), but the reused detail/fit/pipeline/retention pages have no public-mode fallback, so their error states are the only anonymous outcome (covered by F-1).

### PASS
- HTTP public/private boundary (Section 6) — anonymous never reaches private endpoints.
- Data sanitization (Section 7) — demo corpus is fictional, no PII, example.com URLs, 0–100 scales, `DemoDataStore` sole source.
- `/demo/dashboard`, `/demo/jobs`, `/demo/ranked` — fully functional anonymous routes with clean public-hook usage.
- `/demo/applications` data delivery (16 apps, statuses, fit_rating) — functional apart from F-2 display fields.
- Validation/error handling at the public boundary (404/422, no detail leakage).
- Auth-state preservation server-side (valid token survives public+private walkthrough; `PublicRoute` clears nothing).
- Anonymous mutation safety (all writes 401).
- Regression suites (26 + 126 backend, 53 frontend, TS + build).
- Git hygiene (clean tree, HEAD unchanged).
