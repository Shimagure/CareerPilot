## 3. Authoritative Data-Source Mapping

### Portal Health Evidence Flow
```
job_scraper/seen_jobs.json (55 records, all http_403 blocked)
         │
         ▼
job_scraper/portal_health.js  ──ingests──►  job_scraper/portal_health.json
(evidence classification, 7-day window, auto-disable SKILL.md)
         │
         ▼
CP15.6 API must expose:  portal_health.json status row contract
```

### Portal Name Normalization (Critical)
| Source | Format | Example |
|--------|--------|---------|
| `seen_jobs.json` | base name | `indeed`, `jobstreet`, `kalibrr` |
| Portal SKILL dirs | `-search` suffix | `indeed-search`, `jobstreet-search` |
| `portal_health.json` | `-search` suffix | `indeed-search`, `jobstreet-search` |
| PortalDiscoveryExecutor CLIs | base name keys | `indeed`, `jobstreet`, `kalibrr` |

**Normalization rule:** `seen_jobs` base → add `-search` for SKILL/health store.

### Pipeline Health Data Sources
| Health Aspect | Source | Computed By |
|---------------|--------|-------------|
| Pipeline stage/status | `checkpoints.json` | `DataStore.get_pipeline_status()` |
| Active/stale/blocked counts | `seen_jobs.json` | `DataStore.get_health_info()` |
| Portal breakdown | `seen_jobs.json` | `pipeline.py: get_pipeline_health()` → `portal_stats` |
| Retention stats | `seen_jobs.json` | `pipeline.py: get_retention_stats()` |
| Data file existence | Filesystem | `config.verify_data_files()` |

### CP15.5 Health Store Schema (portal_health.json)
```json
{
  "schema_version": "1.0",
  "rolling_window_days": 7,
  "disable_threshold_percent": 50,
  "updated_at": null,
  "portals": {
    "indeed-search": {
      "name": "indeed-search",
      "observations": [
        { "evidence_id": "stable_id|run:<id>", "observed_at": "ISO", "result": "success|explicit_403_blocked|inconclusive", "source": "seen_jobs" }
      ],
      "counts": { "success": 0, "explicit_403_blocked": 0, "inconclusive": 0, "total_observed": 0 },
      "status": "ok|blocked|insufficient_evidence",
      "window": { "explicit_403_blocked": 0, "success": 0, "inconclusive": 0, "total_observed": 0, "block_rate_percent": null },
      "disabled": false,
      "disabled_at": null,
      "disabled_reason": null
    }
    // ... 10 portals total
  }
}
```

### Evidence Classification (from CP15.5)
| seen_jobs Record | Classification | Numerator | Denominator |
|------------------|----------------|-----------|-------------|
| `blocked_reason` ∈ {http_403, 403, forbidden} | `explicit_403_blocked` | ✅ | ✅ |
| `blocked_reason` ∈ {429, rate-limit, block-page, captcha} | `inconclusive` | ❌ | ✅ |
| No `blocked_reason`, usable timestamp | `success` | ❌ | ✅ |
| No usable timestamp / no portal | skipped | ❌ | ❌ |
| No evidence in window | `missing` (derived) | ❌ | ❌ |

**Disable rule:** `explicit_403_blocked / total_observed > 0.50` (strictly greater). Missing data never disables.

## 5. Architecture Rules & Constraints

### Mandatory (from CP15.5 + CLAUDE.md)
1. **Portal name normalization:** `seen_jobs` base → `-search` for health store/SKILL
2. **Atomic SKILL.md edits:** temp file + rename, preserve comment suffix, byte-for-byte body
3. **No automatic re-enable:** manual CLI only
4. **7-day rolling window, >50% threshold:** strict, no weighted scores
5. **Evidence classification:** only `explicit_403_blocked` counts as blocked; 429/block-page = inconclusive
6. **Temp fixture isolation for tests:** `fs.mkdtempSync`, path injection via CLI flags

### Backend Architecture Rules
1. **Read-only API for health status** — CP15.5 owns mutation (auto-disable, manual toggle)
2. **Portal health CLI is source of truth** — API shells out, doesn't reimplement logic
3. **DataStore reads pipeline JSON files** — don't duplicate logic in new router
4. **Thread-safe, LRU-cached stores** — follow `DataStore` / `DemoDataStore` patterns
5. **Pydantic response models** — all new endpoints must have schemas

### What NOT to Do in CP15.6
- ❌ Don't reimplement evidence classification, window calculation, or SKILL.md editing
- ❌ Don't add automatic re-enable (policy: manual only)
- ❌ Don't modify `portal_health.json` schema
- ❌ Don't touch pipeline, scheduler, sync, frontend
- ❌ Don't commit — await explicit instruction
