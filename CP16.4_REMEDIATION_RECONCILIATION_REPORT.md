## 3. STRATEGY COMPARISON: A vs B

### Strategy A: Normalize DB to Enum Names (Uppercase)
| Action | Required |
|--------|----------|
| Update `users.role`: `'user'` → `'USER'` | 26 rows |
| Update `users.status`: `'ACTIVE'` → `'ACTIVE'` (already matches names) | 0 rows |
| Update `resumes.status`: `'UPLOADED'` → `'UPLOADED'` (already matches) | 0 rows |
| Update `search_runs.status`: `'COMPLETED'` → `'COMPLETED'` (already matches) | 0 rows |
| Update `job_sources.*` (when created): use names | N/A |
| Model changes | **NONE** — keep current `Enum(UserRole)` default behavior |

### Strategy B: Change Models to Store Values (Lowercase) with `values_callable`
| Action | Required |
|--------|----------|
| Update `users.status`: `'ACTIVE'` → `'active'` | 26 rows |
| Update `users.role`: `'user'` → `'user'` (already matches) | 0 rows |
| Update `resumes.status`: `'UPLOADED'` → `'uploaded'` | 1+ rows |
| Update `search_runs.status`: `'COMPLETED'` → `'completed'` | 1+ rows |
| Update `user_jobs.status`: N/A (empty) | 0 rows |
| Update `applications.status`: N/A (empty) | 0 rows |
| Model changes | **ALL 8 Enum columns** need `native_enum=False, values_callable=lambda e: [m.value for m in e]` |
| Migration 2b3c alignment | Already uses values — **consistent** |

### Strategy B is SMALLER AND SAFER

**Why Strategy B wins:**
1. **Fewer data changes:** Only `users.status` (26 rows) + `resumes.status` + `search_runs.status` need updates. Strategy A requires changing `users.role` (26 rows) plus all future `job_sources` rows.
2. **Migration 2b3c already uses values:** The CP16.4 migration wrote lowercase values. Strategy B aligns with the *newest* migration, not the oldest.
3. **Less model churn:** Strategy B requires one-line change per Enum column (8 total). Strategy A requires zero model changes but more data migrations.
4. **Tests already expect values:** Test fixtures use `UserStatus.ACTIVE` (enum member) which has `.value = 'active'`. When `create_all` runs, SQLAlchemy stores names by default, but the test *logic* compares against enum members. With Strategy B, the ORM reads `'active'` → maps to `UserStatus.ACTIVE` correctly.
5. **Future-proof:** All new migrations (including corrective ones) can consistently use values.

**Decision: Strategy B — Change models to values-based storage.**
